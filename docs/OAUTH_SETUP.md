# Private developer configuration

Default networking blocks remote calls. All fixtures start in simulator mode.
For each developer account, create a new connection instead of changing the
identity of an already used one. Supply per-connection uppercase environment
variable names for credentials. Add those variables to the private .env only.

LAB_TOKEN_ENCRYPTION_KEY is generated by bootstrap using the Fernet key format.
Keep it private and backed up alongside encrypted database backups. Losing it
requires new OAuth consent. Rotating it requires a deliberate decrypt/re-encrypt
migration which is not included. Never paste tokens into connection forms.
LAB_OAUTH_CLIENT_SECRET is an example name; use distinct names per connection.
STRIPE_TEST_SECRET_KEY must start with sk_test_. Stripe webhook signing secret
must be configured in the provider dashboard and private environment under the
configured name; simulator uses the separately generated LAB_CONNECTOR_SECRET.

Microsoft: register a confidential Web application, exact callback, delegated
Contacts.Read and offline_access. Set the permitted tenant. Code flow uses PKCE.
Zoho: register the exact callback at the US API console; choose a fictional CRM
sandbox organization during consent. Production tokens and other DCs are rejected.
QuickBooks: register a developer sandbox callback and sandbox company. Accounting
scope is required by its Customer API even though this adapter imports contacts.
Each provider has its own redirect URI restrictions. If loopback is not accepted,
use an explicitly approved HTTPS development callback. Public endpoint hosting,
tunnels and DNS are not created by this implementation.

Stripe: register payment_intent.succeeded on a test webhook endpoint, or forward
using the provider's authenticated test CLI into the loopback route. Confirmation
of the created test intent is done in a separately authorized test client or
Stripe dashboard. Card details/client secret are never collected in Odoo here.
An inbound webhook only queues work. An accounting-enabled manager must process
the inbox or deliberately enable the disabled cron with a restricted service user.
